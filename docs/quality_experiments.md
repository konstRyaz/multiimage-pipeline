# Эксперименты фильтрации качества

## Назначение и границы первой версии

Экспериментальный контур отделяет измерение лица от решения о его пригодности.
Он использует уже сохранённые `faces.csv`, `embeddings.npy` и выровненные лица.
InsightFace при переборе политик и порогов не запускается.

В первую версию не входят OFIQ, MediaPipe, MiVOLO, новые нейросетевые модели,
обучение порогов, автоматический поиск коэффициентов и переработка
кластеризации. Начальные пороги `hard_filter_v1` являются отправной точкой, а не
заявлением об оптимальности.

## Архитектура

1. `quality_features.py` сохраняет независимые исходные признаки по схеме
   `quality_features_v1`.
2. `policy.py` применяет версионированные правила. Решение политики не зависит
   от дедупликации и разнообразия.
3. Только принятые лица передаются в дорожки и кластеризацию нового контура.
4. Нормализованные компоненты и мягкий рейтинг рассчитываются отдельно.
5. `selection.py` применяет дедупликацию, временные ограничения, разнообразие и
   предел числа кадров, сохраняя причины невыбора.
6. `experiments.py` атомарно публикует каталог запуска, показатели и сравнение.

Старые сценарии `analyze_faces.py`, `track_faces.py`, `cluster_faces.py`,
`select_faces.py` и `run_pipeline.py` продолжают работать без конфигурации.

## Схема признаков `quality_features_v1`

Связь с тяжёлым кэшем задают неизменяемые `face_id` и исходный
`embedding_index`. Для лица сохраняются:

- `det_score`;
- `bbox_width`, `bbox_height`, `min_face_size`, `relative_face_size`;
- `frame_width`, `frame_height`;
- `border_margin`, `border_margin_relative`;
- исходный `blur_score` и дешёвый `derived_sharpness`;
- `yaw`, `pitch`, `roll` и `pose_available`;
- `brightness_mean`, `dark_fraction`, `bright_fraction`;
- `image_available` и диагностическая ошибка чтения;
- источник, номер кадра и путь к выровненному лицу.

Пропущенные числовые значения записываются как `null`. В частности, отсутствие
позы не превращается в углы, равные нулю. Порог пикселей для долей слишком
тёмных и светлых областей входит в конфигурацию извлечения и отпечаток кэша.

Исходные признаки находятся в `derived/quality_features_v1/features.jsonl`.
Нормализованные компоненты, решение политики и итоговый рейтинг туда не
записываются: они принадлежат конкретному эксперименту.

## Политика

У каждого известного правила есть:

- стабильный идентификатор причины;
- имя признака;
- направление сравнения: `lt`, `gt`, `abs_gt` или `eq`;
- порог;
- поведение при пропуске значения;
- режим.

Режимы:

- `off` — правило полностью отключено и не создаёт причину;
- `shadow` — нарушение попадает в `shadow_reasons`, но лицо остаётся принятым;
- `hard` — нарушение попадает в `reject_reasons`, а лицо отклоняется.

Все нарушенные жёсткие правила сохраняются одновременно. Сравнения строгие:
например, значение, точно равное минимальному порогу, не нарушает правило
`lt`. Неизвестные правила и режимы, отрицательный размер, некорректные пороги и
веса приводят к понятной ошибке до запуска этапов.

### `baseline_v1`

`configs/baseline_v1.json` фиксирует исходные:

- формулу качества с весами `0.30/0.25/0.25/0.20`;
- линейную нормализацию уверенности и размера;
- медианную нормализацию размытия;
- угловую компоненту позы;
- диагностические пороги `0.65`, `32`, `20`, `55/45/45`;
- вес эмбеддинга дорожки `0.5 + quality_score`;
- коэффициенты выбора `0.65/0.20/0.10/0.05`;
- хеш `8×8`, порог Хэмминга `4`, интервал `8`, предел `20`;
- отсутствие жёсткого исключения подозрительных кадров.

Экспериментальный путь функционально эквивалентен прежнему. Возможное
отклонение балла из-за явного промежуточного расчёта и приведения к `float32`
ограничено тестом абсолютной погрешностью `2e-7`. Старый путь не изменил
формулу или порядок выбора.

### `hard_filter_v1 + soft_ranking_v1`

`configs/hard_filter_v1_soft_ranking_v1.json` переводит прежние шесть
диагностических правил в `hard`, жёстко отклоняет недоступное изображение, а
пропущенную позу, границу и освещение пока считает теневыми сигналами.
`soft_ranking_v1` явно использует вынесенные нормализации и веса. Их можно
менять без InsightFace.

## Кэш

Каталог `RUN_DIR/derived/quality_features_v1/` содержит:

- `manifest.json` со статусом, схемой, временем, параметрами извлечения,
  количеством лиц и отпечатком входа;
- `features.jsonl` с одной записью на лицо.

Отпечаток включает SHA-256 `faces.csv` и `embeddings.npy`, параметры дешёвого
извлечения и сведения о выровненных изображениях. Проверяются версия, число и
порядок `face_id` и `embedding_index`. Частичный, повреждённый или
несовместимый кэш безопасно пересчитывается с предупреждением. Тяжёлые файлы
не удаляются.

Принудительный пересчёт только дешёвых признаков:

```bash
python src/run_experiment.py \
  --run-dir runs/example \
  --config configs/baseline_v1.json \
  --force-features
```

Ручная очистка только производного кэша также безопасна:

```bash
rm -r runs/example/derived/quality_features_v1
```

Не удаляйте `faces.csv`, `embeddings.npy` и `aligned_faces/`, если хотите
избежать повторного тяжёлого вывода.

## Запуск

Один эксперимент:

```bash
python src/run_experiment.py \
  --run-dir runs/example \
  --config configs/hard_filter_v1_soft_ranking_v1.json \
  --experiments-dir runs/example/experiments
```

Сравнение на одном кэше:

```bash
python src/compare_experiments.py \
  --run-dir runs/example \
  --configs \
    configs/baseline_v1.json \
    configs/hard_filter_v1_soft_ranking_v1.json \
  --experiments-dir runs/example/experiments
```

Минимальный воспроизводимый пример без InsightFace:

```bash
python src/generate_synthetic.py \
  --output-dir runs/synthetic_quality \
  --seed 42 \
  --overwrite

python src/compare_experiments.py \
  --run-dir runs/synthetic_quality \
  --configs \
    configs/baseline_v1.json \
    configs/hard_filter_v1_soft_ranking_v1.json \
  --labels runs/synthetic_quality/ground_truth.csv
```

То же самое доступно командой `make experiment-synthetic`.

## Разметка

CSV-разметка по умолчанию содержит:

```csv
face_id,is_acceptable,true_person
example_face_001,1,person_a
example_face_002,0,person_a
```

Положительный класс — пригодное, то есть принимаемое изображение. Значения
положительного класса и имена столбцов задаются в секции `labels`. Столбец
личности необязателен, но с ним корректно считаются личности без кадров и
распределение числа кадров до фильтрации. Без него эти показатели ограничены
личностями, которые удалось построить после фильтрации; предупреждение
сохраняется в запуске.

## Каталог запуска

Каждый успешный запуск получает уникальный каталог:

```text
experiments/<run_id>/
├── resolved_config.json
├── run_metadata.json
├── cache_info.json
├── policy_results.csv
├── policy_results.jsonl
├── ranking_results.jsonl
├── metrics.json
├── stage_summaries.json
└── pipeline/
    ├── faces.csv
    ├── embeddings.npy
    ├── tracking/
    ├── clustering/
    └── selected/
```

`run_metadata.json` содержит идентификатор, время, Git-коммит, версии схем,
предупреждения и статус `complete`. До завершения каталог имеет суффикс
`.running`; при ошибке он публикуется с суффиксом `.failed` и файлом
`error.json`, поэтому незавершённый запуск не выглядит успешным и не
перезаписывает предыдущий.

`policy_results` содержит исходные признаки, решение, `reject_reasons` и
`shadow_reasons`. `ranking_results` отдельно содержит нормализованные
компоненты, мягкий рейтинг, личность, решение отбора и причины:
`rejected_by_policy`, `duplicate`, `temporal_proximity`, `pose_diversity`,
`capacity_limit`, `lower_ranking`, `missing_image`,
`unknown_identity_excluded`.

## Показатели и сравнение

`metrics.json` содержит:

- число изображений и лиц, принятые/отклонённые значения и доли;
- срабатывания и пересечения жёстких и теневых причин;
- число кадров по личности до фильтрации, после неё и после выбора;
- личности без оставшихся кадров и статистики распределений;
- причины исключения на выборе;
- время извлечения признаков, политики, дорожек, кластеризации, выбора и всего
  запуска;
- попадание или промах производного кэша;
- при разметке — `precision`, `recall`, `F1`, матрицу ошибок, число
  размеченных/неразмеченных лиц.

Эти показатели описывают фильтрацию и не смешиваются с попарными показателями
качества кластеризации из `evaluate_synthetic.py`.

Сравнение сохраняется в
`experiments/comparisons/<comparison_id>/comparison.json`. В нём есть полные
абсолютные показатели каждого запуска и числовые разницы относительно первой
конфигурации.

## Ограничения и технический долг

- Пороги и коэффициенты пока не калиброваны на размеченном реальном наборе.
- Простые признаки освещения считаются по выровненному лицу, а не по всему
  исходному кадру.
- Исходный `blur_score` остаётся главным признаком совместимости; дополнительная
  резкость нужна для будущих политик.
- Без внешних меток личности невозможно строго восстановить личности, полностью
  удалённые до кластеризации.
- Материализация выбранных изображений включена для совместимости и может быть
  отключена параметром `selection.materialize_images`.
